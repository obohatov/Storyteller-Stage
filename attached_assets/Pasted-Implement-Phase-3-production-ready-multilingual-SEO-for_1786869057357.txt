Implement **Phase 3: production-ready multilingual SEO** for the existing public website.

The current frontend, CMS, database model, authentication, colors, typography, animations and public layouts are approved.

**Do not redesign anything.**

Do not add contact-form delivery, newsletters, analytics, payments, comments or other new product features in this phase.

The site has FOUR locales:

* English: `en`
* Ukrainian: `uk`
* Russian: `ru`
* Dutch: `nl`

Public URLs use locale prefixes.

---

# 1. First audit the current rendering architecture

Before changing anything, verify how the React + Vite + Express app currently delivers public pages.

This is important:

For SEO-critical public routes, `<title>`, meta description, canonical URL, hreflang tags and Open Graph metadata should be present in the **initial HTML response whenever reasonably possible**, rather than depending entirely on client-side JavaScript execution.

If the current Vite SPA does not provide that, implement the **smallest reliable SEO-compatible solution** using the existing Express/Vite architecture.

Possible approaches include server-side HTML metadata injection or prerendering.

Do NOT migrate the project to Next.js or another framework unless absolutely necessary.

Do not rewrite the application architecture merely for SEO.

Before implementation, briefly tell me:

1. how SEO metadata is currently rendered;
2. what approach you will use;
3. why it is appropriate for this project.

---

# 2. SEO metadata from the CMS

For fairy tales and plays, use the CMS translation fields:

* SEO title
* SEO description

If they are empty, generate sensible fallbacks from existing content:

For fairy tales:

* title → work title + author/site name
* description → blurb

For plays:

* title → play title + author/site name
* description → logline or synopsis excerpt

For About and other static public pages, use appropriate locale-specific metadata.

Do not generate fake factual claims.

---

# 3. Page titles

Every indexable page should have a unique localized `<title>`.

Examples of the intended logic:

Home:

`The Storyteller's Stage — Plays & Fairy Tales by [Author]`

Fairy Tales listing:

`Fairy Tales — [Author]`

Individual tale:

`[Fairy Tale Title] — [Author]`

Plays listing:

`Plays — [Author]`

Individual play:

`[Play Title] — [Author]`

About:

`About [Author]`

These are examples of structure, not final copy.

Use the correct localized wording in:

* EN
* UK
* RU
* NL

Do not translate proper names unless the CMS contains a localized version.

---

# 4. Canonical URLs

Add a correct canonical URL to every indexable public page.

Examples:

`https://DOMAIN/en/fairy-tales/example-slug`

`https://DOMAIN/uk/fairy-tales/example-slug`

Each language version should generally canonicalize to **itself**, not to the English version.

Do not canonicalize different legitimate translations into one language.

Use the production domain from environment/configuration rather than hard-coding a temporary Replit development URL.

If a production base URL environment variable is needed, create and document it clearly, for example:

`PUBLIC_SITE_URL`

---

# 5. hreflang

Implement proper multilingual `hreflang` relationships.

Supported language codes:

* `en`
* `uk`
* `ru`
* `nl`

For a work that exists in several published languages, each translation page should reference all other **published** translations of that same work.

Example:

If one fairy tale exists in EN, UK and RU but not NL:

EN page should contain alternates for:

* en
* uk
* ru

Do NOT output an `nl` hreflang for a translation that does not exist or is not published.

Do the same for plays.

For listing pages and static pages, include all available locale versions.

Add `x-default` only where logically appropriate.

If `/` is a neutral language-selection/gateway route, use it as `x-default`.

If `/` simply redirects to the default English site, explain the chosen behavior and implement a sensible `x-default` strategy.

---

# 6. Sitemap

Create a production sitemap.

Prefer:

`/sitemap.xml`

It must contain only public, indexable URLs.

Include:

* localized home pages
* Fairy Tales listing pages
* published fairy-tale translations
* Plays listing pages
* published play translations
* published About pages
* other genuinely public content pages

Do NOT include:

* `/admin`
* API endpoints
* previews
* drafts
* unpublished translations
* authentication routes

The sitemap must reflect database content dynamically or be reliably regenerated when content changes.

Do not require manual editing whenever the author publishes a new work.

Where appropriate, include `lastmod` using actual content update timestamps.

Do not invent modification dates.

---

# 7. robots.txt

Add:

`/robots.txt`

Allow normal crawling of the public website.

Explicitly prevent crawling of areas such as:

* `/admin`
* preview routes if any
* other private/internal paths where appropriate

Reference the sitemap.

Do not accidentally block public CSS, JavaScript or images needed to render the site.

where relevant.

Do not expose draft metadata to search engines.
